# Fix `self_signed_tls_client_auth` Certificate Validation for OIDCC Config Tests

## Overview

OIDCC configuration test variants using `client_auth_type=self_signed_tls_client_auth` fail because the conformance suite's `ValidateClientCertificateForSelfSignedTlsClientAuth` validator expects `client.jwks` to contain a JWK entry with an `x5c` certificate chain matching the presented TLS client certificate. The harness never adds `x5c` to the JWKS, so the suite cannot match the certificate and fails. This plan adds an `x5c`-bearing JWK entry to the client JWKS for `self_signed_tls_client_auth` variants only.

## Current State Analysis

### Root Cause

The validation flow is:

1. The harness sets `client.jwks` (from `client.jwks.json`, bare public keys only) and `client.certificate` (PEM from `client-mtls.pem`) in the plan config (`execute.go:874-883`).
2. The RP presents the mTLS certificate on TLS connections correctly (`runtime_resolution.go:288-293`).
3. The suite extracts the presented certificate and walks every JWK in `client.jwks`, looking for keys with `x5c` chains (`ValidateClientCertificateForSelfSignedTlsClientAuth.java:37-49`).
4. No JWK has `x5c`, so the suite errors: `"Could not find a certificate in client jwks matching the one in the request"`.

### Certificate Details

The mTLS client certificate is generated by `cmd/genfapikeys/main.go:103-144`:
- **Type**: Self-signed X.509
- **Key**: EC P-256
- **Subject DN**: `CN=client-mtls.localhost,O=Lanyard Conformance`
- **SAN DNS**: `client-mtls.localhost`
- **Files**: `conformance/certs/client-mtls.pem` (cert), `conformance/certs/client-mtls-key.pem` (key)

### Key Discoveries

- `appendMTLSPublicKeyToJWKS()` (`execute.go:1071-1114`) already extracts the EC public key from the mTLS cert and builds a JWK entry, but it omits `x5c`. This function is only used for FAPI2 plans.
- `ValidateClientCertificateForSelfSignedTlsClientAuth.java:42-49` requires the **first cert** in a JWK's `x5c` chain to `.equals()` the presented certificate. It does not check DN or SAN — only exact certificate equality.
- The `conformancePublicJWKS()` function (`conformance_keys.go:175-191`) serves only the RSA signing key at `/conformance/jwks/{alias}` — no `x5c`, no EC key.
- The suite may fetch from `jwks_uri` and override `client.jwks` (`AbstractOIDCCClientTest.java:882-899`), so the RP JWKS endpoint must also serve `x5c` for correctness.
- The `rpRuntimeConfig` stores `ClientAuthType` per alias (`runtime_registry.go:42`), and the JWKS endpoint already looks up the runtime config (`runtime_jwks.go:25`), so conditional inclusion is feasible.

## Desired End State

- The harness config includes an `x5c`-bearing EC JWK in `client.jwks` for `self_signed_tls_client_auth` variants.
- The RP JWKS endpoint conditionally includes the same `x5c`-bearing entry when the runtime's auth type is `self_signed_tls_client_auth`.
- All 18 previously-failing `self_signed_tls_client_auth` tests pass.
- No regression in other auth types (`tls_client_auth`, `private_key_jwt`, `client_secret_*`, `none`, `mtls`).

### Verification

Run the OIDCC config conformance suite targeting `self_signed_tls_client_auth` variants and confirm zero failures.

## What We're NOT Doing

- Not modifying the upstream conformance suite code.
- Not changing certificate generation (`cmd/genfapikeys/main.go`).
- Not changing `tls_client_auth` handling (that has its own fix: `2026-04-10-tls-client-auth-metadata-fix.md`).
- Not adding `x5c` to the FAPI2 `appendMTLSPublicKeyToJWKS()` function (FAPI2 doesn't use `self_signed_tls_client_auth`).
- Not changing the `client.jwks.json` fixture file (the x5c entry is added at runtime, not persisted).

## Implementation Approach

Add a new helper `appendSelfSignedCertToJWKS()` that reads the mTLS cert, parses it, and appends an EC JWK with `x5c` containing the DER-encoded certificate. Use it conditionally in both harness config builders and the RP JWKS endpoint.

## Phase 1: Harness Config — Add x5c to JWKS for self_signed_tls_client_auth

### Overview

Add a helper function that appends an `x5c`-bearing JWK entry to the JWKS, and call it in `buildPlanConfig` and `buildStandaloneModuleConfig` when the auth type is `self_signed_tls_client_auth`.

### Changes Required

#### 1. New helper function `appendSelfSignedCertToJWKS`
**File**: `conformance/harness/execute.go`
**Location**: After `appendMTLSPublicKeyToJWKS()` (after line 1115)

This function:
1. Calls `loadClientMTLSCert()` to get the cert PEM
2. Parses the PEM to get the `x509.Certificate`
3. Extracts the EC public key coordinates (same logic as `appendMTLSPublicKeyToJWKS`)
4. Encodes the DER certificate bytes as base64 (standard encoding, not URL-safe) for `x5c`
5. Builds a JWK entry with `kty`, `crv`, `kid`, `alg`, `use`, `x`, `y`, and `x5c`
6. Appends to the JWKS keys array

```go
func appendSelfSignedCertToJWKS(jwks map[string]any) map[string]any {
    certPEM, _, err := loadClientMTLSCert()
    if err != nil {
        return jwks
    }
    block, _ := pem.Decode([]byte(certPEM))
    if block == nil {
        return jwks
    }
    cert, err := x509.ParseCertificate(block.Bytes)
    if err != nil {
        return jwks
    }
    pubKey, ok := cert.PublicKey.(*ecdsa.PublicKey)
    if !ok {
        return jwks
    }
    curve := pubKey.Curve
    byteLen := (curve.Params().BitSize + 7) / 8
    xBytes := make([]byte, byteLen)
    yBytes := make([]byte, byteLen)
    pubKey.X.FillBytes(xBytes)
    pubKey.Y.FillBytes(yBytes)

    x5cEntry := base64.StdEncoding.EncodeToString(cert.Raw)

    keyJWK := map[string]any{
        "kty": "EC",
        "crv": "P-256",
        "kid": "client-mtls",
        "alg": "ES256",
        "use": "sig",
        "x":   base64.RawURLEncoding.EncodeToString(xBytes),
        "y":   base64.RawURLEncoding.EncodeToString(yBytes),
        "x5c": []string{x5cEntry},
    }
    keys, _ := jwks["keys"].([]any)
    jwks["keys"] = append(keys, keyJWK)
    return jwks
}
```

**Note on `x5c` encoding**: RFC 7517 §4.1.6 says each `x5c` member is a base64-encoded (not base64url) DER certificate. The NimbusDS library used by the suite (`jwk.getParsedX509CertChain()`) expects standard base64 encoding.

**File**: `conformance/harness/execute.go`

Current code at line 874 loads JWKS for both `private_key_jwt` and `self_signed_tls_client_auth`. After loading the JWKS for `self_signed_tls_client_auth`, call `appendSelfSignedCertToJWKS`:


**Note**: The `request_object`/`request_uri` branch (line 891-897) may overwrite `jwks` after this code runs. For `self_signed_tls_client_auth` combined with `request_object` or `request_uri`, the x5c cert must survive that overwrite. Two approaches:

**Option A (recommended)**: Apply `appendSelfSignedCertToJWKS` after the request-object JWKS assignment, at the end of the function before the RAR check. This ensures x5c is added regardless of which branch set the JWKS.

**Option B**: Also add x5c in the request-object branch when auth type is `self_signed_tls_client_auth`.

I recommend Option A: add a single conditional append after line 897 (after the request-object branch):

```go
if requestTypeUsesSignedRequestObject(requestType) {

    cfg["client"].(map[string]any)["jwks"] = clientJWKS
    cfg["client2"].(map[string]any)["jwks"] = clientJWKS
    cfg["client"].(map[string]any)["request_object_signing_alg"] = "PS256"
    cfg["client2"].(map[string]any)["request_object_signing_alg"] = "PS256"

if authType == "self_signed_tls_client_auth" {
    for _, c := range []map[string]any{
        cfg["client"].(map[string]any),
        cfg["client2"].(map[string]any),
    } {
        if jwks, ok := c["jwks"].(map[string]any); ok {

    }

```

This ensures x5c is appended to whichever JWKS was set, regardless of which branch set it. Move the `authType` variable declaration before the `requestTypeUsesSignedRequestObject` check so it's in scope.

### Overview

### Changes Required

#### 1. Modify `conformancePublicJWKS` to accept auth type
**File**: `cmd/example-rp/conformance_keys.go`
**Lines**: 175-191

Add a parameter for auth type and conditionally append the x5c-bearing JWK:

```go
func conformancePublicJWKS(authType string) (map[string]any, error) {
    keys, err := loadConformanceKeySet()
    if err != nil {
        return nil, err
    }

    jwksKeys := []map[string]any{{
        "kty": "RSA",
        "use": "sig",
        "kid": keys.rsaKeyID,
        "alg": keys.rsaAlg,
        "n":   base64.RawURLEncoding.EncodeToString(keys.rsaPrivateKey.PublicKey.N.Bytes()),
        "e":   base64.RawURLEncoding.EncodeToString(big.NewInt(int64(keys.rsaPrivateKey.PublicKey.E)).Bytes()),
    }}

    if strings.EqualFold(strings.TrimSpace(authType), "self_signed_tls_client_auth") {
        certJWK, err := selfSignedCertJWK(keys)
        if err == nil {
            jwksKeys = append(jwksKeys, certJWK)
        }
    }

    return map[string]any{
        "keys": jwksKeys,
    }, nil
}
```

#### 2. Add `selfSignedCertJWK` helper
**File**: `cmd/example-rp/conformance_keys.go`
**Location**: After `conformancePublicJWKS`

```go
func selfSignedCertJWK(keys conformanceKeySet) (map[string]any, error) {
    if keys.mtlsCert == nil || len(keys.mtlsCert.Certificate) == 0 {
        return nil, fmt.Errorf("no mTLS certificate available")
    }
    cert, err := x509.ParseCertificate(keys.mtlsCert.Certificate[0])
    if err != nil {
        return nil, fmt.Errorf("parse mTLS cert: %w", err)
    }
    pubKey, ok := cert.PublicKey.(*ecdsa.PublicKey)
    if !ok {
        return nil, fmt.Errorf("mTLS cert public key is not ECDSA")
    }
    byteLen := (pubKey.Curve.Params().BitSize + 7) / 8
    xBytes := make([]byte, byteLen)
    yBytes := make([]byte, byteLen)
    pubKey.X.FillBytes(xBytes)
    pubKey.Y.FillBytes(yBytes)

    return map[string]any{
        "kty": "EC",
        "crv": "P-256",
        "kid": "client-mtls",
        "alg": "ES256",
        "use": "sig",
        "x":   base64.RawURLEncoding.EncodeToString(xBytes),
        "y":   base64.RawURLEncoding.EncodeToString(yBytes),
        "x5c": []string{base64.StdEncoding.EncodeToString(cert.Raw)},
    }, nil
}
```

```go
func TestBuildPlanConfig_OIDCConfigSelfSignedTlsClientAuth_ContainsX5C(t *testing.T) {
    cfg := buildPlanConfig(map[string]string{
        "client_auth_type":    "self_signed_tls_client_auth",
        "request_type":        "plain_http_request",
        "client_registration": "static_client",
        "response_mode":       "default",
    }, "alias-test", 5)

    client, ok := cfg["client"].(map[string]any)
    if !ok {
        t.Fatal("client config missing")
    }
    jwks, ok := client["jwks"].(map[string]any)
    if !ok {
        t.Fatal("client.jwks missing")
    }
    keys, ok := jwks["keys"].([]any)
    if !ok {
        t.Fatal("jwks keys missing")
    }

    foundX5C := false
    for _, rawKey := range keys {
        key, ok := rawKey.(map[string]any)
        if !ok {
            continue
        }
        if x5c, ok := key["x5c"].([]any); ok && len(x5c) > 0 {
            foundX5C = true
            if key["kid"] != "client-mtls" {
                t.Errorf("x5c key kid = %q, want %q", key["kid"], "client-mtls")
            }
            if key["kty"] != "EC" {
                t.Errorf("x5c key kty = %q, want %q", key["kty"], "EC")
            }
            break
        }
    }
    if !foundX5C {
        t.Fatal("no JWK with x5c found in client.jwks")
    }
}
```
