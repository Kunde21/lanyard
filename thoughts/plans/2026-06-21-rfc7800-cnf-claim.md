# RFC 7800: PoP Key Semantics (`cnf` claim) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement RFC 7800 (Proof-of-Possession Key Semantics for JWTs) by adding the `cnf` (confirmation) claim: a typed `Confirmation` value, RFC 7638 JWK thumbprint (`jkt`) and X.509 SHA-256 certificate thumbprint (`x5t#S256`) computation, binding-verification helpers, and integration into ID Token claims and the DPoP flow. This closes the last gap in Lanyard's sender-constraint story (DPoP + mTLS already produce proofs, but nothing exposes or verifies the resulting token binding).

**Architecture:** RFC 7800 defines `cnf` as a JWT claim whose members bind a token to a proof-of-possession key. Two members matter in practice for Lanyard:

- `jkt` — RFC 7638 JWK Thumbprint (SHA-256). Used by **DPoP** (RFC 9449 §7): a DPoP-bound access token carries `cnf.jkt` equal to the thumbprint of the DPoP public key.
- `x5t#S256` — X.509 certificate SHA-256 thumbprint over the DER encoding. Used by **mTLS** (RFC 8705 §3): an mTLS-bound access token carries `cnf.x5t#S256` equal to the client certificate thumbprint.

Lanyard is a **Relying Party**, not a resource server. So `cnf` here means: (a) parse the claim into a typed value wherever tokens/claims surface, (b) compute the expected binding value from the RP's own DPoP key / mTLS certificate, and (c) let callers verify a token's binding matches the RP's key material. We deliberately do **not** implement resource-server-side access-token signature verification (out of scope); callers verifying untrusted tokens must do that themselves.

**Tech Stack:** Go, `rp` package, `github.com/go-jose/go-jose/v4` (`JSONWebKey.Thumbprint` implements RFC 7638 — do **not** reimplement the canonical thumbprint), `github.com/google/go-cmp/cmp` for test assertions.

**Dependencies:**
- `github.com/go-jose/go-jose/v4` v4.1.3 — already in `go.mod`, already exposes `JSONWebKey.Thumbprint(crypto.Hash)`.
- Task 8 (introspection) is **gated** on the unmerged `feat/token-introspection` branch landing on master. Skip Task 8 until then; the rest of the plan is independent of it.

**Scope (non-goals):**
- No resource-server token verification of AS-signed JWT access tokens (callers do this).
- No `jwe` decryption (parsed opaquely only).
- No FAPI 2.0 Grant Management (separate future effort; RFC 7800 is a prerequisite, not the full feature).

## Design Decisions

### D1: Use go-jose's `JSONWebKey.Thumbprint`, don't hand-roll

RFC 7638's canonical thumbprint (lexicographic member sort, no whitespace, fixed key-member subset per kty) is fiddly and easy to get wrong. `go-jose/v4` already implements it correctly. Build a `jose.JSONWebKey{Key: pub}` and call `.Thumbprint(crypto.SHA256)`. Base64url-encode (raw, no padding) the result.

### D2: Refactor DPoP JWK construction to share the source of truth

`rp/dpop.go` currently builds the public JWK as `map[string]any` via `rsaJWK()`/`ecdsaJWK()` for the DPoP proof header. The `cnf.jkt` we emit/verify must be byte-identical to the thumbprint of that same JWK. To guarantee they can never drift, refactor `dpop.go` to build a single `jose.JSONWebKey` and derive (a) the header JWK via `.MarshalJSON()` and (b) the thumbprint via `.Thumbprint()`. This removes the bespoke `rsaJWK`/`ecdsaJWK` map builders (they are not used elsewhere — verified).

### D3: `Confirmation` parses all RFC 7800 members; verifies only `jkt` + `x5t#S256`

```go
type Confirmation struct {
    JWK    json.RawMessage `json:"jwk,omitempty"`       // §3.2 full JWK (deprecated, parsed opaquely)
    JKT    string          `json:"jkt,omitempty"`       // RFC 7638 thumbprint — DPoP
    X5T256 string          `json:"x5t#S256,omitempty"`  // X.509 SHA-256 — mTLS
    X5C    []string        `json:"x5c,omitempty"`
    X5U    string          `json:"x5u,omitempty"`
    X5T    string          `json:"x5t,omitempty"`       // SHA-1 variant, parsed not trusted
    Kid    string          `json:"kid,omitempty"`       // deprecated
    JWE    string          `json:"jwe,omitempty"`       // §3.4 encrypted key, opaque
}
```

Note the JSON tag `json:"x5t#S256"` — `#` is legal in a JSON member name and Go struct tags handle it fine. At most one binding member is expected per RFC 7800 §3.1; we parse defensively but only `VerifyDPoPBinding`/`VerifyMTLSBinding` assert specific members.

### D4: `JWKThumbprint` accepts stdlib private keys only

Matches the existing constraint in `dpop.go`'s `buildDPoPProof` switch: `*rsa.PrivateKey` and `*ecdsa.PrivateKey`. The custom `rsaPrivateKey`/`ecdsaPrivateKey` types in `key_provider.go` exist only for `parseJWK` and are never passed to `NewStaticClientKeyProvider` in practice (verified: `cmd/example-rp/conformance_keys.go` passes `*rsa.PrivateKey`). Return a typed error for unsupported keys rather than panic.

### D5: Access-token `cnf` decoding is signature-unverified (with documented caveat)

When an RP obtains a DPoP-bound access token over the trusted token-endpoint TLS channel, it can decode the JWT (if it is one) to self-check that the AS bound it to the RP's DPoP key. We provide `ParseAccessTokenConfirmation(rawJWT)` that decodes header.payload without signature verification. **Godoc must warn** that this is unsafe for tokens received from untrusted sources (resource-server use), which must verify signatures via the AS JWKS first.

### D6: New sentinel errors

```go
ErrTokenUnbound         = errors.New("token is not sender-constrained")
ErrTokenBindingMismatch = errors.New("token binding mismatch")
```

Added to `rp/errors.go`. Wrap with `%w` for `errors.Is` support.

package rp

import "encoding/json"

// Confirmation represents the RFC 7800 "cnf" (confirmation) claim, which binds
// a JWT to a proof-of-possession key. At most one binding member is expected
// (RFC 7800 §3.1); the two that matter for sender-constrained tokens are:
//
//   - JKT (RFC 7638 JWK Thumbprint) — used by DPoP (RFC 9449).
//   - X5T256 (x5t#S256, X.509 SHA-256 certificate thumbprint) — used by mTLS (RFC 8705).
//
// Other members (jwk, x5c, x5u, x5t, kid, jwe) are parsed for completeness but
// not enforced by VerifyDPoPBinding / VerifyMTLSBinding.
type Confirmation struct {
	JWK    json.RawMessage `json:"jwk,omitempty"`
	JKT    string          `json:"jkt,omitempty"`
	X5T256 string          `json:"x5t#S256,omitempty"`
	X5C    []string        `json:"x5c,omitempty"`
	X5U    string          `json:"x5u,omitempty"`
	X5T    string          `json:"x5t,omitempty"`
	Kid    string          `json:"kid,omitempty"`
	JWE    string          `json:"jwe,omitempty"`
}

// IsBound reports whether the confirmation carries a recognized binding member
// (jkt or x5t#S256).
func (c Confirmation) IsBound() bool {
	return c.JKT != "" || c.X5T256 != ""
}
```

import (
	"crypto"
	"crypto/ecdsa"
	"crypto/rsa"
	"crypto/sha256"
	"encoding/base64"
	"fmt"

	"github.com/go-jose/go-jose/v4"
)

// JWKThumbprint returns the base64url-encoded RFC 7638 SHA-256 JWK Thumbprint
// of the public key derived from priv. Supports *rsa.PrivateKey and
// *ecdsa.PrivateKey (the same types accepted by DPoP proof generation).
// Unsupported key types return an error.
func JWKThumbprint(priv crypto.PrivateKey) (string, error) {
	var pub crypto.PublicKey
	switch k := priv.(type) {
	case *rsa.PrivateKey:
		pub = &k.PublicKey
	case *ecdsa.PrivateKey:
		pub = &k.PublicKey
	default:
		return "", fmt.Errorf("%w: unsupported key type %T", ErrTokenBindingMismatch, priv)
	}
	jwk := jose.JSONWebKey{Key: pub}
	digest, err := jwk.Thumbprint(crypto.SHA256)
	if err != nil {
		return "", fmt.Errorf("compute JWK thumbprint: %w", err)
	}
	return base64.RawURLEncoding.EncodeToString(digest), nil
}
```

import "crypto/x509"

// X509CertThumbprint returns the base64url-encoded SHA-256 thumbprint of the
// DER encoding of cert's leaf — the value carried in the RFC 7800 cnf claim
// member "x5t#S256" for mTLS-bound tokens (RFC 8705 §3). Returns "" for nil.
func X509CertThumbprint(cert *x509.Certificate) string {
	if cert == nil {
		return ""
	}
	sum := sha256.Sum256(cert.Raw)
	return base64.RawURLEncoding.EncodeToString(sum[:])
}

// VerifyDPoPBinding reports whether c binds the token to the public key
// derived from priv (DPoP). Returns ErrTokenUnbound if no jkt member is
// present, or an error wrapping ErrTokenBindingMismatch on mismatch.
func (c Confirmation) VerifyDPoPBinding(priv crypto.PrivateKey) error {
	if c.JKT == "" {
		return ErrTokenUnbound
	}
	got, err := JWKThumbprint(priv)
	if err != nil {
		return fmt.Errorf("%w: %v", ErrTokenBindingMismatch, err)
	}
	if subtle.ConstantTimeCompare([]byte(c.JKT), []byte(got)) != 1 {
		return fmt.Errorf("%w: jkt mismatch", ErrTokenBindingMismatch)
	}
	return nil
}

// VerifyMTLSBinding reports whether c binds the token to cert's leaf
// certificate (mTLS x5t#S256). Returns ErrTokenUnbound if no x5t#S256 member
// is present, or an error wrapping ErrTokenBindingMismatch on mismatch.
func (c Confirmation) VerifyMTLSBinding(cert *x509.Certificate) error {
	if c.X5T256 == "" {
		return ErrTokenUnbound
	}
	got := X509CertThumbprint(cert)
	if subtle.ConstantTimeCompare([]byte(c.X5T256), []byte(got)) != 1 {
		return fmt.Errorf("%w: x5t#S256 mismatch", ErrTokenBindingMismatch)
	}
	return nil
}
```

Add `"crypto/subtle"` to imports. Constant-time compare is required because thumbprint strings are derived from secret key material (project rule: constant-time comparison for secrets).

import "strings"

// ParseAccessTokenConfirmation decodes the cnf claim from a JWT access token
// WITHOUT verifying its signature.
//
// SECURITY: This is safe ONLY when the token was obtained over a trusted
// channel (e.g. directly from the token endpoint over TLS). For tokens
// received from untrusted sources (resource-server use), you MUST first
// verify the JWT signature against the authorization server's JWKS before
// trusting any claim. This helper performs no signature or expiry checks.
//
// Returns ErrTokenUnbound (wrapped) if the JWT has no cnf claim.
func ParseAccessTokenConfirmation(rawJWT string) (Confirmation, error) {
	parts := strings.Split(rawJWT, ".")
	if len(parts) != 3 {
		return Confirmation{}, fmt.Errorf("invalid JWT: expected 3 parts, got %d", len(parts))
	}
	payload, err := base64.RawURLEncoding.DecodeString(parts[1])
	if err != nil {
		return Confirmation{}, fmt.Errorf("decode JWT payload: %w", err)
	}
	var claims struct {
		Cnf *Confirmation `json:"cnf"`
	}
	if err := json.Unmarshal(payload, &claims); err != nil {
		return Confirmation{}, fmt.Errorf("decode JWT claims: %w", err)
	}
	if claims.Cnf == nil {
		return Confirmation{}, fmt.Errorf("%w: access token has no cnf claim", ErrTokenUnbound)
	}
	return *claims.Cnf, nil
}
```
